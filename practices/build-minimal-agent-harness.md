# 从零搭 Agent Harness：先建三模块，再加可观测回归

> **出处** — [@omarsar0](https://x.com/omarsar0/status/2099545598156288292) · 采集于 2026-09-15
>
> **原作者说法**：他最早从 ReAct 入手，用自己熟悉的编程语言从零实现 Harness。最小结构只有三块：支持多模型的 LLM 模块、工具模块，以及把两者串起来的 Agent Loop。学习阶段先保持系统提示词短小，记录 Loop、模型和工具调用的输入输出，再用一组小而多样的任务反复运行和人工检查；理解主循环后才逐步加入 memory、skills 和 subagents。若目标是尽快建设生产系统，而不是理解原理，可以直接选 Pi SDK 或 LangChain 等现成 Harness。

以下“最小接口”“回归账本”和“适用边界”是本仓库补充的工程化落地，不是原作者逐字方案。原作者经验未经第三方验证。

## 它要解决的问题

很多人第一次做 Agent 就同时引入框架、记忆、RAG、Skills、MCP、多代理和长期任务。结果一旦失败，很难判断是模型、工具、循环、上下文还是框架默认行为出了问题。

这条实践的核心不是“自己重写一个更好的框架”，而是用最少组件看清 Agent 的基本动力学：模型为什么选这个工具、工具结果怎样回到上下文、循环为什么继续或停止。

## 最小三模块

### 1. LLM 模块

只负责把消息发给模型，并返回统一结果。至少固定这些字段：

- `model`：实际使用的模型，不依赖隐式默认值；
- `messages`：本轮真实输入；
- `tool_calls`：模型请求的工具与参数；
- `usage`：输入、输出和缓存 token；
- `finish_reason`：模型为何停止。

学习版可以先接一个模型，但接口要允许替换第二个模型做对照。系统提示词保持短小，新增规则必须能对应一个观察到的失败。

### 2. 工具模块

每个工具都有明确的输入 schema、输出 schema、超时和错误类型。是否使用 MCP 不是关键；关键是工具失败必须作为结构化结果返回，不能吞掉异常，也不能把整段无关日志塞回上下文。

### 3. Agent Loop

循环只做四件事：请求模型、校验工具调用、执行工具、把结果追加回消息。必须提前写死停止条件：

- 模型给出最终答案；
- 达到最大轮数或时间预算；
- 同一工具和参数连续重复；
- 工具返回不可恢复错误；
- 命中需要人工批准的动作。

没有停止条件的 Loop 不是自治，只是失控重试。

## 先做可观测，再加能力

给每次运行分配 `run_id`，把事件按顺序记成一条轨迹：

```text
run_started
model_requested
model_responded
tool_requested
tool_completed | tool_failed
run_stopped
```

每个事件记录时间、模型、工具名、耗时、token、错误类型和前后消息数量。日志默认保存摘要或哈希；提示词、文件内容、凭据与客户数据需要脱敏或不落盘。

可观测性的目标不是“什么都记”，而是能回答四个问题：哪里慢、哪里贵、哪里重复、哪里做错。

## 建一个小型回归账本

先准备 6—12 个覆盖不同形状的任务：纯问答、一次工具调用、多步工具调用、工具超时、无权限动作、找不到答案。每次修改 Loop、提示词或模型后，重新运行同一组任务并记录：

| 指标 | 为什么要看 |
|---|---|
| 任务是否完成 | 最终结果有没有达到外部判据 |
| 工具调用次数 | 是否出现绕路或重复 |
| 总轮数与耗时 | 是否陷入长循环 |
| token 与费用 | 改进是否只是把成本转移了 |
| 失败类型 | 模型、工具、循环还是权限问题 |

学习阶段可以人工检查，但判据要尽量外部化：文件是否存在、测试退出码、结构化字段是否正确。只让 Agent 自己评价自己，无法形成回归。

## 扩展顺序

三模块稳定后，再按真实缺口逐项添加：

1. 需要复用操作流程时，加 Skill；
2. 需要跨会话保留稳定事实时，加 Memory；
3. 单个上下文装不下且子任务可独立验收时，加 Subagent；
4. 需要跨工具复用接口时，再把函数封装成 MCP；
5. 人工检查成为瓶颈时，加自动 grader，但保留失败抽查。

每次只加一层，并用同一组任务对照。否则性能变好也不知道是哪一层起作用，性能变差更找不到该删什么。

## 适用边界

- **适合学习原理和验证架构，不适合用来证明自研框架优于成熟框架。** 生产环境还需要鉴权、隔离、重试、追踪、并发、成本控制和版本迁移。
- **ReAct 是起点，不是万能循环。** 高风险写操作、长事务和严格工作流更适合显式状态机或审批图。
- **MCP 是互操作选择，不是首日必需品。** 只有一个本地函数时，先把输入输出和错误契约做好，比先搭协议层更重要。
- **不要一开始就加多代理。** 主循环尚不可观测时，多代理只会把同一个未知问题复制多份。
- **日志可能成为新的敏感数据源。** 生产日志要限制保留期、访问权和字段；能用计数、摘要与哈希回答的问题，不保存全文。
- **人工检查不能无限扩展。** 当任务集扩大后，应把明确规则变成自动检查，同时保留代表性人工抽查和失败样本复盘。

## 今天就能开始

选一个不会产生外部副作用的小任务，在一个文件里实现三模块；只给 Agent 两个只读工具，最大循环设为 8 轮。先跑 6 个固定任务，把每轮模型和工具事件记录下来。看完轨迹后，只修最明显的一类失败，再跑同一组任务对比。

如果第一天就需要 memory、几十个 skills 和一群 subagents，说明范围还没有缩到“学习 Harness”这件事上。
