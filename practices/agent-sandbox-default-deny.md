# Agent 沙箱默认拒绝：任务文件进，密钥与任意网络不进

> **出处** — [@AndrewYNg](https://x.com/AndrewYNg/status/2104660347730969087) · 采集于 2026-09-29
> **原作者说法**：OpenWorker 在 NVIDIA OpenShell 上让每个 Agent 的命令运行于沙箱。只有任务相关文件进入沙箱；API keys、浏览器登录凭据与任意网站访问默认不可用。限制由确定性代码实施，而不是靠提示词；全部动作进入监控与审计日志。
> 原作者团队的项目实践，未经第三方验证。下文的授权模型、验收清单与失败边界是本仓库补充的工程化落地。

## 它要解决的问题

Agent 需要文件、命令和网络才能完成真实任务，但同一组能力也能读取宿主机资料、外传密钥或操作无关系统。仅在 prompt 中写“不要访问其他文件”“不要泄露密钥”不是安全边界：模型可能误解、遗忘，或被不可信内容注入。

可靠边界必须满足两点：**默认拿不到**，而且**Agent 自己改不了规则和审计记录**。

## 默认拒绝的四层设计

1. **文件系统只注入任务包。** 把明确允许的源文件、测试和说明复制或挂载进隔离工作区。宿主 home、浏览器 profile、同步盘与其他项目默认不可见。
2. **凭据不进入通用上下文。** 密钥由独立 broker 按工具、目标和时间发放短期令牌；Agent 只得到完成当前动作所需的最小权限。能由宿主代调用的，就不把原始 secret 交给模型。
3. **网络默认关闭，按域名与动作放行。** 需要联网时通过受控代理开放明确目的地，记录请求元数据，并限制上传体积、方法和重试次数。不能把“能访问互联网”当作一个布尔开关。
4. **日志写到沙箱之外。** 命令、工具调用、文件变更、网络出站、批准人和最终结果进入 Agent 无法修改的审计面；高风险动作在执行前生成可读预览。

## 一次任务的授权流程

1. **列任务清单。** 写明输入文件、允许修改的目录、必须访问的服务、预期产物和完成判据。
2. **生成最小权限配置。** 每项能力对应一个明确理由；没有理由的文件、网络和凭据保持关闭。
3. **先以只读方式运行。** 让 Agent 给出计划、拟访问资源和拟执行动作，验证范围没有漂移。
4. **逐项开放写权限。** 文件写入、外部提交、发消息、支付或删除各用独立审批，不能用一次批准覆盖后续所有动作。
5. **执行独立 checker。** 测试产物正确性，并核对访问日志中没有越界资源、异常上传或未批准的工具调用。
6. **撤销临时权限。** 任务结束后回收令牌、关闭网络例外、保存审计记录，并清理沙箱而不是保留一个永久高权限环境。

## 验收清单

- 不提供凭据时，Agent 仍无法从环境变量、shell 历史、浏览器或相邻项目找到它。
- 未在允许列表中的域名、IP、端口和 HTTP 方法会失败，并留下可定位记录。
- Agent 无法修改权限策略、审计日志和 checker。
- 写操作可回滚；外部不可逆动作在执行前需要人类批准。
- 超时、循环、并发和上传量都有硬上限，达到上限后安全停止并生成 handoff。
- 任务结束后短期令牌失效，沙箱中的残留文件不会自动晋升为长期记忆或 skill。

## 远程推理再加三层去身份化

> **补充出处** — [@VitalikButerin](https://x.com/VitalikButerin/status/2106537633056969024) · 采集于 2026-10-04
> **原作者说法**：在处理个人健康与旅行数据的实验中，他让本地 Qwen 模型编排任务，只把最小化后的查询交给远程前沿模型；支付经 zkAPI，网络经 Tor。作者同时指出 Tor 延迟高、请求构造还不理想，而且披露越少，远程模型能提供的帮助也越少。
> 这是原作者的个人实验，未经独立验证。下面的实施顺序与验收项是本仓库补充的工程化落地。

当任务确实需要远程模型、又不能把原始敏感数据直接送出去时，把“隐私”拆成三条互不替代的链路：

1. **内容最小化。** 本地模型先读取原始资料，删除姓名、地址、账号、精确时间地点和无关细节，再把问题改写成远程模型完成推理所需的最小事实集合。
2. **支付去身份。** 不让远程服务从付款账户直接关联到个人身份；若使用代理支付或隐私支付服务，先确认其信誉、合规性、日志政策与故障恢复方式。
3. **网络去身份。** 通过受控代理或隐私网络减少 IP 与长期会话标识关联；每次请求仍应避免稳定的自定义 header、固定客户端指纹和可关联的长连接。

落地时先做一组对照测试：同一任务分别用完整数据、本地最小化数据和完全本地模型执行，比较答案质量、泄漏字段、延迟与费用。只有最小化版本在不暴露禁止字段的前提下达到质量门槛，才允许进入日常流程。

额外验收：

- 记录发送给远程模型的最终请求，而不是只记录本地原始输入；用自动扫描检查姓名、邮箱、手机号、精确位置和内部标识是否仍然存在。
- 假设写作风格、罕见事实组合和时间序列也能成为指纹；“删掉姓名”不等于匿名。
- 为远程模型设置独立的域名 allowlist、调用次数、单次费用和总预算；支付或网络层失效时默认停止，不回退为直接连接。
- 远程返回只作为建议，不自动写回敏感档案或触发医疗、财务等高风险动作。

## 适用边界

- 沙箱减少误操作与数据外泄，不证明宿主、内核、虚拟化层或依赖没有漏洞；高敏感任务仍需专门威胁建模和渗透测试。
- 某些任务确实需要浏览器登录态、生产数据或广泛网络。正确做法是按步骤临时授权和记录，不是为了方便永久关闭隔离。
- 日志本身可能含敏感数据。应做脱敏、访问控制与保留期限，不能把审计系统变成新的泄漏源。
- 默认拒绝会增加配置成本。优先为高风险写操作、密钥、浏览器凭据和数据出站建立边界，再逐步覆盖低风险工具。
- OpenShell/OpenWorker 是原作者的实现选择，不是唯一方案；容器、轻量虚拟机或受控远程执行也可以满足同一安全契约。
- 本地改写、zkAPI 与 Tor 只能降低部分关联风险，不能证明匿名。请求内容、时序、客户端指纹、服务商日志和多个弱标识的组合仍可能重新识别用户。
- 最小披露与答案质量存在直接权衡。医疗、法律等高风险任务如果删掉关键背景后无法可靠作答，应转向受合同和合规约束的受信服务，而不是强行匿名调用。

## 最小结论

不要问 Agent“可不可以信任”。先让它默认看不到密钥、出不了任意网络、改不了审计记录；确实需要的权限，再按任务、按动作、按时间逐项发放。
