# 换 Agent 模型,先跑一天真实工作流

> **出处** — [@kunchenguid](https://x.com/kunchenguid/status/2102234191639257399) · 采集于 2026-09-22
> **原作者说法**:作者把新模型放进自己长期使用的 Agent harness 里运行一整天,没有用公开 benchmark 或 3D 游戏演示直接拍板。他重点观察四件事:系统提示遵循、跨回合稳定性、执行动作前是否谨慎确认,以及速度与额度消耗。一天后,他认为新模型更守规则、更稳定、更保守,但也更慢、额度消耗更快;未量化的部分明确保留为后续观察。
>
> 下文的对照表、记录方法与放行闸门是本仓库的工程化整理,不是原作者逐字给出的通用评测协议。

## 为什么公开 benchmark 不够

Agent 模型不是只回答一道题。它要在同一套系统提示、工具、权限和上下文里持续工作。公开分数无法直接告诉你:

- 会不会忽略仓库约定或安全规则;
- 跨十几个回合后行为是否漂移;
- 模糊操作时会确认还是擅自推进;
- 成功一次需要多少轮、多少 token 和多少返工。

所以新模型先进入**影子模式或可回滚任务队列**,不要直接替换主力。

## 一天对照怎么跑

1. **固定 harness。** 系统提示、工具版本、权限、上下文上限和 effort 保持一致,一次只换模型。
2. **选真实任务。** 至少包含规则明确的例行任务、需要诊断的复杂任务、模糊授权任务和长程任务各一项。
3. **保留同一 checker。** 测试、产物、页面状态与外部结果使用同一套验证器,不让候选模型自己改判据。
4. **逐回合记证据。** 记录模型是否遵守系统提示、是否重复、何时请求确认、何时需要人工纠正。
5. **统一结算。** 汇总成功率、首次通过轮数、总输入/输出 token、墙钟时间、额度消耗和人工返工分钟数。

不要只挑模型最亮眼的回合。稳定性看的是**最差回合与异常频率**,不是最高峰。

## 四个行为维度

### 提示遵循

用几条容易被忽略但可核查的规则作探针,例如“红色测试不得跳过”“对外发送前必须确认”。观察模型是否在压力下仍执行。

### 稳定性

记录同类任务的方差:是否一会儿极聪明、一会儿犯基础错误。平均分相同,低方差模型通常更适合无人值守流程。

### 行动保守度

准备授权清晰、授权模糊和明确禁止三类任务。理想模型在第一类执行,第二类询问,第三类停止。过度保守会增加人工往返,过度激进会放大副作用。

### 资源消耗

同时记录速度与额度。模型更慢可能来自更长思考、更多输出或工具重试;“月费相同”不代表任务成本相同。

## 放行规则

候选模型只有在固定任务集上达到质量下限,且没有新增高风险违规,才进入主流程。费用或速度改善不能抵消安全与正确性回退。

先灰度一部分任务,保留旧模型回退。连续多天观察没有明显漂移后,再扩大范围。

## 适用边界

一天实跑适合筛选候选和发现行为差异,不能证明长期可靠。低频故障、版本变化、供应商限流和周额度只能靠更长时间监控。

作者的结论来自单个 harness 与一天个人使用,未经独立复现;具体模型排名不可外推。公开 benchmark 也不是无用,它适合发现候选与构造任务,但最终放行仍应基于自己的真实工作流、固定 checker 和可回滚灰度。
