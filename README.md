# x-ai-practices

从 X(Twitter)上捞到的 AI 工程实践沉淀。

每天读 X 上的 AI 讨论会刷过大量信息,但绝大多数是新闻和噪音。这个仓库只留**能照做的那一小部分**——一条实践进来之前得先过一关:*读完之后,我今天就能改点什么?* 答不上来的不收。

## 收录标准

| 收 | 不收 |
|---|---|
| 有明确的操作步骤,读完能直接改工作流 | 只有结论没有做法(「agent 是未来」) |
| 说清了适用边界和失效场景 | 「这个太炸了,细节看下面链接」式的书签诱饵 |
| 原推正文自带干货 | 干货全在外链、正文只负责钓鱼 |
| 作者讲的是自己实际在跑的东西 | 二手转述、拼盘式「10 个技巧」 |

每篇都标注**出处推文链接**与**采集日期**,并注明哪些部分是原作者的说法、哪些是本仓库补充的工程化落地。原作者的经验多为个人实践、未经第三方验证,照抄前请自行判断。

## 目录

### 流程工程 (Process Engineering)

比起把提示词写得更好听,更有效的往往是改流程本身。

- [**异构终审闸门**](practices/cross-vendor-judge-gate.md) — 让另一家供应商的模型给你的产出打分,低分打回重跑。用来对抗单一模型自评时的同源偏见。
- [**读推理轨迹,不只读答案**](practices/read-the-reasoning-trace.md) — 在模型作答前中断它,把 thinking traces 当成设计反馈来读。
- [**把指令切成按需加载的 skill**](practices/on-demand-skill-loading.md) — 用触发式描述替代越写越长的全局提示词,让上下文默认保持干净。
