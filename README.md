# x-ai-practices

从 X(Twitter)上捞到的 AI 工程实践沉淀。

每天读 X 上的 AI 讨论会刷过大量信息,但绝大多数是新闻和噪音。这个仓库只留**能照做的那一小部分**——一条实践进来之前得先过一关:*读完之后,我今天就能改点什么?* 答不上来的不收。

## 收录标准

| 收 | 不收 |
|---|---|
| 有明确的操作步骤,读完能直接改工作流 | 只有结论没有做法(「agent 是未来」) |
| 说清了适用边界和失效场景 | 「这个太炸了,细节看下面链接」式的书签诱饵 |
| 原推正文自带干货 | 干货全在外链、正文只负责钓鱼 |
| 作者讲的是自己实际在跑的东西 | 二手转述、拼盘式「10 个技巧」 |

每篇都标注**出处推文链接**与**采集日期**,并注明哪些部分是原作者的说法、哪些是本仓库补充的工程化落地。原作者的经验多为个人实践、未经第三方验证,照抄前请自行判断。

## 目录

### 流程工程 (Process Engineering)

比起把提示词写得更好听,更有效的往往是改流程本身。

- [**把外层循环交出去之前,先补上三样东西**](practices/outer-loop-three-parts.md) — 真实的停止判据、上下文修剪、独立的检查者。核心一条:`passes` 不能是 agent 自己能改的字符串,得是 checker 的退出码。另附收敛护栏(单调性检查 + 卡死升级)专治「循环跑不完」,以及**第零步:按下 goal 之前先让它做一轮调研**——目标定不准的话,停止判据再硬,验的也只是一件错事。
- [**异构终审闸门**](practices/cross-vendor-judge-gate.md) — 让另一家供应商的模型给你的产出打分,低分打回重跑。用来对抗单一模型自评时的同源偏见。
- [**读推理轨迹,不只读答案**](practices/read-the-reasoning-trace.md) — 在模型作答前中断它,把 thinking traces 当成设计反馈来读。
- [**把指令切成按需加载的 skill**](practices/on-demand-skill-loading.md) — 用触发式描述替代越写越长的全局提示词,让上下文默认保持干净。
- [**让 Skill 从人类反馈中进化,而不是让它自己瞎改**](practices/human-feedback-skill-evolution.md) — 把执行与改进分开:人类在 PR/工单等原工作流里纠正,原始轨迹只读留证,持久 Wiki 累积理解,改进器只提交候选 diff;通过留出集、权限过滤、人工批准和版本回滚后才发布,并防止不可信轨迹被晋升为长期指令。
- [**先量再砍:把上下文当预算来管**](practices/context-budget-hygiene.md) — 先量出「你还没打第一个字时窗口里已经有什么」,再逐项削减:全局指令文件压到 200 行内、禁令写成权限设置而非句子、能用 CLI 就别用 MCP(命令只返回你要的几行,MCP 每次把完整结果倒进窗口)。含五个削减位置、三条会话纪律、**工具也要分阶段暴露**(开场只挂 2 个工具、进入执行阶段再解锁全部;对照实验里得分从 91 升到 98/99——模型只有「规划」和「执行」两个稳定档位,一上来全摊开就卡在中间),**窗口终究会满时的交接文档接力**(到触发线就让模型产出 handoff 文档、下个会话读它续上,把「清空」换成「交接」),**不清空也能瘦的中间档**(不结束会话、让模型原地删掉废弃方案与失败尝试,重生成只含目标/约束/决策/进度/未决/下一步的六要素摘要,并声明此后以摘要为准——第三步才是机关,否则它照样回头引用你刚否掉的路径;代价依次是「就地清理 < 交接 < 清空」),**2026-08-20 增补**:**顺序也算钱**(提示词缓存按前缀匹配,前面动一处、后面全部重算——不变的项目规则/`AGENTS.md`/开发规范放前面,每轮都变的需求与报错放后面,并且别频繁切模型和工具配置,因为它们也在前缀里;推倒重建指令文件要当成一次「有计划的缓存失效」集中做,零散小改是缓存最贵的敌人),以及一条对称的**官方口径**——**什么时候该反过来把窗口调大**(工具默认上限通常低于模型支持上限,改配置文件顶层三个键即可;但官方明说默认值是按性能与成本调过的,调大不是解锁免费档位,而是主动把权衡点从「快且便宜」挪到「记得多」,所以顺序必须是先砍再买)。
  - **2026-09-02 增补:**把单次 Agent 账单拆成六个可测环节——模型路由、Context、缓存、工具加载、工具往返和代码库检索;每次只改一环,用固定任务、checker、成功率、Token、时延与费用做对照,避免“省了单价却多跑一遍”。
- [**别自己从零写规范:抄一线团队开源出来的工程 Skill**](practices/steal-open-sourced-engineering-skills.md) — 成熟项目正在把 agent 配置和工程约定一起提交进仓库(`.agents/` `.claude/` `AGENTS.md`),那是公开、免费、被真实评审磨过的方法论。含一份核实过的 11 个工程 Skill 清单、先看哪几个、移植时必改的四处,以及最关键的边界:**skill 只负责「怎么做」,「做没做成」仍然得由退出码说了算**。**2026-08-18 增补**:同一个动作还有一个更大的版本——**别自己描述文风,去挂一份有名字的公开规范**(让模型读 Google 开发者文档风格指南并建成 skill,治「AI 腔」),原因是这类规范在训练数据里有海量正例,一个专有名词唤起的约定比你写一整段形容词更准;含四步落地结构与「治文风不治事实」的边界。
- [**把审阅搬到产物上,而不是留在对话里**](practices/visual-review-loop.md) — 在浏览器里直接改字 + 划词批注,把反馈从「描述」降级成「已完成的编辑」,删掉 agent 理解这一环。含阻塞式 poll 如何真正闭合人在回路,以及 npm 版本落后三周的安装坑。 **2026-09-03 增补**:3D 页面先约束图片与模型素材,再逐项检查纹理、光照、重叠、留白和真实滚动;区分原作者经验与补充的验收、预算边界。
- [**把日常维护拆成每天自动跑的例程**](practices/daily-maintenance-routines.md) — 死代码清理、重复抽象合并、崩溃模糊测试做成每日例程,产出永远收敛成小 PR 走人工审查;**做错时去调例程提示词、明天重跑,而不是这次手工兜底**。含「先加日志再删」这个把静态分析问题换成观测问题的手法,以及一个常被忽略的真瓶颈——例程条数该按团队每天的**审查带宽**倒推,而不是按智能体能跑多少(原作者合并率约 46%,意味着过半 PR 要被关掉)。
- [**私有开发,公开快照**](practices/private-development-public-snapshots.md) — 完整设计文档、测试、形式化规范与实验脚本留在私有开发仓库,公开仓库只接收经过验证的发布快照。把 `wiki/design/` 的持续审阅变成主要开发活动,用 2–10 台临时云主机做实验、2–4 个编码 Agent 会话并行;含快照发布清单、外部贡献入口和防止私有仓库变成单点真相的边界。

### 多代理编排 (Multi-Agent Orchestration)

一个 agent 干不完的活怎么拆出去,以及拆出去之后怎么不失控。

- [**让本地 agent 只当协调者,把活派给云端子代理**](practices/coordinator-cloud-subagents.md) — 协调者不写代码,只拆任务、发任务、验收;真正的收益是上下文隔离而非并行。含七种失败模式,以及 Anthropic 与 Cognition 两家相反立场的调和。**2026-08-20 增补**:**上下文隔离的反面——同一份上下文被复制了 N 遍**。前面讲的都是「你怎么派任务」,这条讲的是「它可能不等你派」:有用户拿本地 token 账本记录到一次未经批准的自动扇出,把一个 issue 扩成 11 个并行子代理、每个都完整复制系统指令与对话历史,6.08 亿 token 里约 5.14 亿(85%)花在子代理上(个人取证,未核实)。关键区分是**单价 vs 基数**——「子代理继承主模型」讲的是单价,这条讲的是同一份上下文被计费 11 次,两者会相乘;含四步排查动作与「额度刚重置就掉得快 = 先查扇出」这个自查信号。**2026-08-21 增补**:**官方给了第一诊断入口**——Claude Code 负责人对「额度为什么烧这么快」给出的口径是先跑 `/usage` 看分解,绝大多数情况只有三个原因(极端并行 / 跑飞的循环 / 效率极差的 skill 或 plugin);价值不在技巧而在**把抱怨变成了有诊断树的工程问题**,且官方把「极端并行」列在第一位,与上一条的个人取证独立指向同一处。含先后顺序建议(先 1 分钟看分项、再半小时查扇出)与「这是推文回复口径、非文档」的边界。
  - **2026-09-04 增补：Manager Loop。** 经理只拆阶段、派发与验收，实现者只做当前阶段；共享看板记录可验证进度，停滞时重规划，最后做全局回归。明确排除无 checker 的主观任务与未经批准的高并发。

### 模型溯源与评测 (Model Provenance & Evaluation)

模型不公开身份、评测结果来源不明时,先找可重复的外部证据,再讨论归因。

- [**用 token 差分给匿名模型做词表指纹**](practices/tokenizer-fingerprint-by-token-delta.md) — 固定请求外壳,用“基准文本”与“基准文本 + 特征后缀”的 `prompt_tokens` 差值消掉固定系统提示词,再与多个官方端点交叉比较。含多语言探针矩阵、置信度分级与边界:它最多支持“共享 tokenizer / 同一词表家族”,不能单独证明具体模型身份。
